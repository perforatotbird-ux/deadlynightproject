## 1. Назначение документа

Документ фиксирует, **какие звуки нужны уровню 1, откуда они взяты, на каких условиях и как встраиваются в Godot**. Он не дублирует мастер-документ: координаты POI, скорости игрока и параметры рубки берутся оттуда, здесь — только аудиослой.

Три задачи:

1. Дать композитору/звукорежиссёру и программисту **общий список событий с ID**, чтобы код и ассеты не расходились.
2. Зафиксировать **происхождение и лицензию** каждого файла — до того, как проект уйдёт в публичную демонстрацию.
3. Отделить **готовое к интеграции** от **плейсхолдеров**, которые нужно заменить.

> **Важная оговорка.** Отбор файлов выполнен по метаданным, названиям и замерам громкости — прослушивание в этой сессии не проводилось. Раздел 9 содержит обязательный чек-лист прослушивания перед тем, как считать кит финальным.

## 2. Аудио-дирекция

### 2.1. Тональный ориентир

Референс из мастер-документа — *The Long Dark*, но в стилизованном исполнении. Концепт-арт (`K:\concept art\world.jpg`, `world 2.png`, `общая концепция мира.png`) задаёт палитру: тёплый вечерний свет, выветренное дерево, ржавый металл, сырая земля. Это **не** мультяшный low-poly и **не** фотореализм — промежуточная «нарисованная» плотность.

Отсюда звуковой вектор:

| Принцип | Что это значит на практике |
|---|---|
| **Диегетика прежде всего** | 90% звука — то, что реально звучит в мире. Музыка появляется редко и ненадолго. |
| **Ширина важнее громкости** | Лес звучит стереопанорамой и глубиной, а не уровнем. Тихий, но объёмный микс. |
| **Тишина — инструмент** | Провалы в эмбиенте (птицы замолчали) работают сильнее любого аккорда. |
| **Материал слышно** | Берёза, ель, бук и дуб звучат по-разному. Игрок должен узнавать породу по удару. |
| **Шахта — другой мир** | Резкая смена акустики на пороге: реверберация, низкий гул, отсутствие птиц. |

### 2.2. Чего избегаем

- «Кинематографичного» whoosh на каждое действие — уровень про ремесло, не про экшен.
- Синтетических «гейм-звуков» (8-bit, xylophone, sci-fi UI) — в локальном паке они есть, но стилистически чужие. Оставлены только как временные заглушки.
- Постоянного музыкального слоя. Если игрок замечает музыку — она написана неверно.

## 3. Технический каркас в Godot 4.7

### 3.1. Шины

```
Master  ── Limiter (-1 dBFS)
├── Music        -8 dB
├── Ambience     -6 dB
├── World3D      -4 dB   (позиционные SFX снаружи)
│   └── World3D_Mine  + Reverb   (внутри штольни)
├── Player       -2 dB   (непозиционные: шаги, топор, дыхание)
└── UI           -5 dB
```

`World3D_Mine` — отдельная шина с `AudioEffectReverb` (room_size 0.75, damping 0.5, wet 0.35, dry 0.65). Переключение делается на входе/выходе из `MineInterior.tscn` одновременным изменением `bus` у активных `AudioStreamPlayer3D` и фейдом эмбиента — это дешевле, чем городить `Area3D`-реверб на каждый источник.

`AudioEffectLimiter` на Master обязателен: рубка даёт пики, которые иначе срежет сам движок.

### 3.2. Типы нод

| Задача | Нода | Настройки |
|---|---|---|
| Фоновые петли (лес, ветер) | `AudioStreamPlayer` | `bus = Ambience`, loop on |
| Точечные источники (ручей, река, портал) | `AudioStreamPlayer3D` | `attenuation_model = Inverse Square`, `unit_size = 6…10`, `max_distance` по таблице, `doppler_tracking = Off` |
| Вагонетка, обвал | `AudioStreamPlayer3D` | `doppler_tracking = Physics` только для движущейся вагонетки |
| Шаги, удары топора | `AudioStreamPlayer` + `AudioStreamRandomizer` | `playback_mode = Random (No Repeats)`, `random_pitch = 0.94…1.06`, `random_volume_offset_db = -2…0` |
| UI | `AudioStreamPlayer` | `bus = UI`, полифония 1 |

`AudioStreamRandomizer` — ключевая нода: она снимает «пулемётность» шагов без ручного кода. Для каждого набора поверхности достаточно одного плеера со списком из 4 файлов.

### 3.3. Бюджет голосов

| Категория | Одновременно | Комментарий |
|---|---|---|
| Ambience | 6 | лес, ветер, ручей, река, шахта, капель |
| Шаги | 2 | перекрытие при быстрой смене поверхности |
| Топор и дерево | 3 | удар + щепа + треск |
| Мир (пропсы) | 8 | осыпь, кусты, мост |
| UI | 2 | |
| **Итого 3D** | **≤ 24** | выше — заметно на GTX 1060 при 60 FPS |

### 3.4. Импорт ассетов

- **WAV** (короткие one-shot, < 2 с): `Import → Loop Mode: Disabled`. Не включать `Force 8-bit`, не включать `Trim`.
- **WAV-петли** (`amb_wind_canopy.wav`, `amb_stream_loop.wav`): `Loop Mode: Forward`, точки входа/выхода — по фактическим границам петли в файле.
- **OGG**: `AudioStreamOggVorbis.loop = true` для петель, иначе false.
- **MP3**: `amb_forest_bed.mp3` технически зацикливается, но даёт щелчок на стыке из-за padding. **Задача:** перекодировать в OGG перед финальной сборкой (см. раздел 9).
- Целевой формат мастера: 48 кГц, 16 бит. Часть локальных файлов — 44.1 кГц, это допустимо: Godot ресемплирует на импорте.

## 5. Гейн-стейджинг

Замеры сделаны по фактическим файлам (`data/audio_kit_report.csv`, 103 записи).

**Системная проблема:** 23 файла из локального пака имеют пик 0.0 dBFS — пак сведён «в полку», без запаса. Импортированные из Sonniss файлы, наоборот, стоят на −3…−6 dBFS. Если не выровнять, шаги и удары топора будут заметно громче новых эмбиентов.

Рекомендация: одним проходом применить **−3 дБ ко всем файлам из локального пака**, затем точечно поправить выбросы из таблицы ниже. Это дешевле, чем прописывать `volume_db` каждому событию в коде.

### 5.1. Проблемные места

| Файл | Peak, dBFS | Проблема | Коррекция |
|---|---|---|---|
| `footsteps/step_gravel_04.wav` | −0.22 | на 10 дБ громче соседей по набору | −8 дБ при импорте |
| `footsteps/step_rock_02.wav` | −2.12 | выбивается из серии | −6 дБ |
| `footsteps/step_wood_04.wav` | −6.62 | громче остальных «деревянных» | −3 дБ |
| `ui/ui_hover.wav` | −23.15 | почти неслышим | +18 дБ |
| `ui/ui_overweight.wav` | −21.25 | тише, чем должен быть сигнал тревоги | +16 дБ |
| `ui/ui_objective.wav` | −20.66 | тихий | +14 дБ |
| `ambience/amb_drip_bed.wav` | 0.0 (RMS −17.6) | перекомпрессирован, петля «давит» | −6 дБ, RMS-нормализация |

### 5.2. Целевые уровни

- One-shot SFX: пик **−3 dBFS**, RMS −18…−14 dBFS.
- Петли эмбиента: RMS **−26…−22 dBFS** (пики не нормировать — они естественные).
- UI: пик −6 dBFS, RMS −20 dBFS.

Коррекции применяются либо в `AudioStreamPlayer.volume_db` на уровне сцены, либо однократной нормализацией файлов. **Предпочтительно второе** — иначе цифры расползутся по коду.

### 6.2. Определение поверхности под ногами

Два подхода, оба валидны:

1. **MVP (быстро):** `RayCast3D` вниз на 1.2 м → `collider.collision_layer` или группа (`surface_grass`, `surface_gravel`, …). Требует разметки коллизий при генерации мира.
2. **Целевой:** выборка веса из splatmap по UV точки попадания. Работает автоматически на всей карте 4000×4000 без ручной разметки и точно соответствует визуальному покрытию. Рекомендуется после промта A3.

До реализации любого из подходов шаги играют `STEP_GRASS` — это безопасный дефолт.

### 6.3. Переход в шахту

На `Area3D` портала: за 0.5 с (как в мастер-документе) гасится `AMB_FOREST_BED` и `AMB_WIND_CANOPY`, поднимается `AMB_DRIP_BED`, активные 3D-источники переводятся на шину `World3D_Mine`. Обратный переход — зеркально. Резкий срез недопустим: игрок должен слышать, как лес «закрывается».

### 7.2. Что лежит в `K:\concept art\_audio_sources\`

Скачанные библиотеки сохранены как есть, согласно договорённости:

```
K:\concept art\_audio_sources\
├── sonniss_gdc2026\          # Sonniss GDC 2026, 5 частей, 6.92 ГБ (все целы)
│   └── _staging\             # извлечённые кандидаты до конвертации
├── opengameart\              # CC0-ассеты + распакованный набор на 75 файлов
└── README.md                 # что откуда и на каких условиях
```

**Sonniss GDC Game Audio Bundle 2026** — 484 файла, 6.92 ГБ, royalty-free, **атрибуция не требуется**, коммерческое использование разрешено бессрочно и без ограничения проектов. Все пять частей скачаны и проверены.

Важная особенность бандла: это **кураторская выборка**, а не полные библиотеки. 484 файла по 96/192 кГц — по одному-два сэмпла из каждой библиотеки вендора. Поэтому в нём не оказалось ни петли реки, ни пещерных эмбиентов, ни отдельной серии ударов топора по породам. Зато нашлось то, что сложно синтезировать: луг с коньками, рум-тон шахты, дыхание, реальные замахи.

### 7.3. Конвейер импорта

Длинные записи из Sonniss нельзя класть в проект как есть: 96 кГц / 24 бит, до 100 МБ на файл. Обработка автоматизирована в `scripts/audio/import_sonniss.py`:

1. `ffmpeg` → 48 кГц, стерео, OGG q4 для петель и WAV PCM16 для one-shot.
2. `loudnorm` под целевой уровень категории: −26 LUFS для эмбиента, −28 для музыки, −18 для one-shot.
3. Монтажи («swing to thud impact», 61.8 с) режутся автоматически: `silencedetect` находит паузы, сегменты 0.35–3.0 с сохраняются как отдельные вариации.

Результат — 17 файлов, 14 МБ вместо 320 МБ исходников. Разброс пиков у восьми нарезанных замахов — 1.2 дБ, дополнительная коррекция не нужна.

## 9. Обязательный чек-лист прослушивания

Перед тем как считать кит финальным:

1. **Прослушать все 103 файла** и отбраковать те, что не подходят по тону. Особое внимание — `step_mud_*` (взяты из набора «vinyl», могут звучать как синтетика) и `step_litter_*` (взяты из «snow» — скрип снега вместо сухих листьев).
2. **Проверить петли на стык.** `amb_wind_canopy.wav` (8.61 с), `amb_stream_loop.wav` (4.02 с), `amb_drip_bed.wav` (17.14 с) могут щёлкать. `amb_forest_bed.mp3` заведомо требует перекодирования в OGG. Новые петли из Sonniss (`amb_meadow_spring`, `mine_roomtone_loop`, `mus_tension_drone`, `amb_water_lap`) — записи без закольцованных границ, стык надо слушать обязательно.
3. **Собрать тестовую сцену**: поляна + 5 деревьев + брод. Пройти маршрут `SPAWN → FORD` и оценить, не утомляет ли эмбиент за 3 минуты. Особенно `amb_meadow_spring`: коньки в записи повторяются каждые 86 секунд, это слышно.
4. **Проверить различимость пород** на слух: срубить по одному дереву каждой породы подряд.
5. **Сверить замахи с анимацией.** Восемь вариантов `axe_swing_real_*` нарезаны из записи «замах → удар», то есть содержат удар в конце. Если анимация замаха короче 0.6 с — часть вариантов будет запаздывать.
6. **Замерить реальную нагрузку** — 24 голоса на GTX 1060 при 60 FPS.

## 11. Открытые вопросы

1. **Происхождение локального пака.** `400 Sounds Pack` лежит в `K:\concept art\` без файла лицензии. Для внутреннего прототипа это неважно, но перед публичным билдом нужно подтвердить право использования — иначе заменить на CC0-аналоги.
2. **Музыка.** Стоит ли вообще вводить музыкальный слой в MVP, или ограничиться диегетикой? Текущие заглушки скорее вредят.
3. **Голос игрока.** Дыхание и реакции — это уже характер персонажа. Нужно решение, есть ли у героя голос.
4. **Локализация UI-звуков.** Сейчас UI-звуки нейтральные; если появится озвученный интерфейс, часть придётся переделать.
