# Deadly Night — исправление меню и отчёт проверки

## Основа и окружение

- Репозиторий: https://github.com/perforatotbird-ux/deadlynightproject
- Исходный коммит: `fb26b1edf69a15879912c8e3c51c6e24043e4e5b`.
- Рабочая ветка: `fix/menu-settings-layout`.
- Движок проверки: `Godot 4.7.2.stable.official.ed1daf0bf`, Linux x86_64.
- Ресурсы Git LFS загружены перед импортом. Настройки и сохранения тестировались в отдельном пользовательском каталоге, не в данных реального прохождения.

## Причина проблемы отображения

Дочерние экраны главного меню добавлялись непосредственно к корневому Control, тогда как основная навигация находилась в CanvasLayer 1. В результате настройки рисовались под главным меню. Кроме того, присваивание `anchors_preset` программно созданным контейнерам не выполняло необходимую настройку якорей и отступов: центрирующий контейнер и затемнение не занимали экран, панель появлялась в левом верхнем углу.

## Исправлено

1. Дочерние экраны главного меню размещаются в его UI CanvasLayer; пока открыт экран, кнопки заднего меню отключены. Повторное открытие одного экрана блокируется.
2. Полноэкранные Control/ColorRect/CenterContainer получают `set_anchors_and_offsets_preset(PRESET_FULL_RECT)`; панели снова центрируются, затемнение покрывает экран.
3. Настройки имеют ограниченную размером окна панель. Все четыре вкладки прокручиваются; двухколоночная перегруженная таблица назначений заменена одной колонкой. Футер остаётся вне прокрутки.
4. Подтверждения выводятся отдельным верхним CanvasLayer. Escape закрывает только верхний диалог; клавиатурный фокус ограничен текущим экраном/подтверждением и возвращается после закрытия.
5. Пауза не перехватывает Escape своего дочернего экрана. Настройки/загрузка возвращаются в паузу, а не сразу в игру; фоновые кнопки скрыты.
6. При успешной загрузке из паузы меню закрывается, пауза снимается, мышь возвращается игре. При неуспешной загрузке экран остаётся открытым с сообщением.
7. Ошибка «Продолжить» не оставляет игрока за чёрным FadeRect. Показывается причина, главный экран восстанавливается.
8. Таймер смены разрешения корректно завершает диалог при таймауте, отмене и подтверждении. Текст таймера больше не сбрасывает фокус каждую секунду. Неподтверждённое разрешение не записывается как постоянное; уход с экрана возвращает прежний режим. Сброс настроек тоже использует подтверждение небезопасной смены экрана.
9. Звук предварительно прослушивается без изменения сохранённой конфигурации. «Назад» отменяет предпросмотр; «Применить» сохраняет его. Назначения клавиш также редактируются в черновике; Escape отменяет захват, конфликтующая клавиша не назначается молча.
10. Настройки FOV, покачивания, HUD, теней и дальности камеры подключены к игре. Переназначение клавиш применяется к контроллеру и InputMap, включая прыжок и пять слотов пояса. На пояс выводятся актуальные клавиши.
11. Пауза, инвентарь и потеря фокуса сбрасывают удержание удара; закрытие меню не продолжает рубку без нового нажатия. UI-звуки работают во время паузы.
12. Инициализация SettingsManager/SaveManager не выполняется повторно при отложенном добавлении в дерево. Освобождаются временные сцены деревьев после извлечения мешей: переходы меню → игра → меню не оставляют четыре сиротских экземпляра деревьев.
13. Повторное обновление списка сохранений не оставляет старые карточки до конца кадра; длинные названия сокращаются с подсказкой.

## Границы проверки

- GUI запускался через Xvfb / Mesa llvmpipe / **Compatibility**, а не на целевой Windows/Forward+. Рендерер по умолчанию проекта не изменён.
- Полный графический рендер большого леса не подтверждён в этом окружении. Для воспроизводимой проверки игровых окон использован тестовый флаг `--hide-world-rendering`: реальная MapViewer и её логика загружаются, но её WorldMap скрыт при графическом прогоне. Это только код теста, не ограничение или изменение обычной игры.
- Результат **не** подтверждает 60 FPS, GTX 1060, производительность леса, Windows fullscreen/мультимониторность, все разрешения или аппаратную работу VSync. На виртуальном экране есть ожидаемое предупреждение об отсутствии управления VSync.
- Скриншоты проверены для 1280×720; реальная отмена разрешения проверена с 1366×768. Не заявляется проверка всех соотношений сторон.
- Проверена работа выбора сложности в UI и перехода в игру, а не баланс/наличие всех описанных survival-механик.
- У части исходных тестов и при принудительном завершении из подтверждения остаются сообщения очистки ObjectDB/resources at exit. Они не учтены как пройденные функциональные проверки и не скрываются в приложенных журналах. Новый полный навигационный прогон завершился без таких ошибок очистки после устранения сиротских сцен деревьев.
- В GitHub изменения не отправлялись. Это локальное исправление, патч и исходники; не готовый Windows-билд.

## Как воспроизвести тесты

Используйте **отдельный** профиль: тесты навигации намеренно создают/удаляют тестовые слоты и отказываются запускаться, если пользовательский путь не содержит `deadly-night-test`.

Linux:

```bash
export XDG_DATA_HOME=/tmp/deadly-night-test
Godot_v4.7.2-stable_linux.x86_64 --headless --path . --script tests/test_menu_navigation.gd
Godot_v4.7.2-stable_linux.x86_64 --headless --path . --script tests/test_inventory_menu_layout.gd
Godot_v4.7.2-stable_linux.x86_64 --headless --path . --script tests/test_menu_exit.gd
Godot_v4.7.2-stable_linux.x86_64 --headless --path . --script tests/test_menu_exit.gd -- --pause
```

GUI, если нет достаточного GPU для леса:

```bash
Godot_v4.7.2-stable_linux.x86_64 --path . --rendering-method gl_compatibility --script tests/test_menu_navigation.gd -- --hide-world-rendering --screenshots=/tmp/deadly-night-test/screenshots
Godot_v4.7.2-stable_linux.x86_64 --path . --rendering-method gl_compatibility --script tests/test_inventory_menu_layout.gd -- --screenshots=/tmp/deadly-night-test/screenshots
```

Windows/PowerShell: запускайте в новой оболочке, чтобы временный APPDATA не затронул другие приложения.

```powershell
$env:APPDATA = Join-Path $env:TEMP 'deadly-night-test'
New-Item -ItemType Directory -Force $env:APPDATA | Out-Null
& .\Godot\godot.exe --headless --path . --script tests/test_menu_navigation.gd
& .\Godot\godot.exe --headless --path . --script tests/test_inventory_menu_layout.gd
```

После этого требуется ручной приёмочный проход на Windows/Forward+: открыть меню мышью и клавиатурой, проверить оконный/безрамочный/полноэкранный режимы, таймаут разрешения, возврат из настроек паузы, сохранение/загрузку и выход. Тестовый пользовательский профиль не заменяет реальные сохранения игрока.
